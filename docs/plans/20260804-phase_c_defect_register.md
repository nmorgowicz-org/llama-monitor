### `discussions` scenario

| Screenshot | Expected | Actual | Severity | Status |
|---|---|---|---|---|
| `discussions-feed-qwen-froggeric.png`, `discussions-feed-gemma4-google.png` | "Manage template…" opens the shared Chat Template Lifecycle modal over the Spawn Wizard, showing Current/Updates/Version History/Community Fixes | Underlying Spawn Wizard step rendered with no modal open at all — Community Fixes content entirely absent | **High — real production bug, not a test artifact** | **Fixed.** Root cause: `#chat-template-lifecycle-modal` was physically nested inside `#preset-modal` in `static/index.html` (a leftover from before the modal became a shared component in Phase B1/B2). `#preset-modal` is `.modal-overlay`, which is `display:none` when the Preset Editor is closed — and `display:none` on an ancestor hides the entire subtree regardless of the descendant's own `position:fixed`/`display:flex`. So the "shared" lifecycle modal only ever rendered correctly when opened *from* the Preset Editor (its ancestor happened to already be open); opened from the Spawn Wizard (Preset Editor closed), it collapsed to 0×0 and was invisible — confirmed via `getBoundingClientRect()` diagnostics (`rect: {x:0,y:0,w:0,h:0}` despite `display:flex`/`opacity:1`/`.open` class all correctly set). Fixed by moving the modal markup to a top-level sibling just before `</body>`, independent of any caller's own modal container. Rebuilt (`cargo build --release`) and re-verified both Qwen and Gemma4 captures, plus a `preset-editor` regression run — all show the modal correctly. |
