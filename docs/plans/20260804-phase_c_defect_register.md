## Tier 1 — chat-template surfaces

### `preset-editor` scenario

| Screenshot | Expected | Actual | Severity | Status |
|---|---|---|---|---|
| `preset-editor-chat-template-row-light.png` | Status line reflects the field's actual value (a custom template path was set) | Status line read "Chat template: built-in — using the model's built-in template" despite the field showing a real `.jinja` path | Medium (test-realism bug, not user-facing — see root cause) | **Fixed** in `tests/ui/capture/scenarios/presets/preset-editor.mjs`: the scenario set `templateInput.value` directly without dispatching `change`, and `updatePresetChatTemplateStatusLine()` in `presets.js` is only wired to the input's `change` listener. A real user typing+blurring fires `change` natively, so this was a scenario-fidelity gap, not a shipped bug — but it produced a misleading screenshot. Fixed by dispatching `change` after setting the value, matching the pattern already used for `modal-model-path`. |
| `preset-editor-discussions-feed.png` vs `preset-editor-lifecycle-modal-light.png` | Two distinct screenshots for two distinct capture intents | Pixel-identical — both captured the same open "Manage template…" modal at the same scroll state. `fullPage: true` in Puppeteer captures full scroll height regardless of `scrollIntoView` calls, so the "scroll to Community Fixes" step had no effect | Low (redundant, not incorrect) | **Fixed**: removed the redundant `discussions-feed` capture block; Community Fixes is now part of the single consolidated lifecycle-modal capture, consistent with the actual (post-B1/B2) IA where there's no standalone Discussions view anymore. |
| `preset-editor-lifecycle-modal-dark.png` | Dark-theme legibility comparable to the rest of the app (e.g. `preset-editor-advanced-tab.png`, which renders at full contrast) | "Version history" / "Community fixes" list-item text renders at ~2.2:1 contrast against the panel background (`--color-text-muted` on `--pe-panel-bg` dark gradient), well under WCAG's 3:1 floor for muted/secondary text. Confirmed via direct pixel sampling (panel bg ≈ rgb(28,34,41), text ≈ rgb(70-95,75-100,80-105)), not a screenshot rendering artifact. | **Medium-high** — real accessibility/legibility defect, dark theme only | **Not fixed** — logged for follow-up. Needs a CSS pass on `.chat-template-lifecycle-section-content` / list-item text color in `:root:not([data-theme="light"])` scope in `static/css/modal-premium.css` (~line 2940-2970 region), likely swapping `--color-text-muted` for a lighter dark-theme-specific token in this context, or lightening `--pe-panel-bg`. |
